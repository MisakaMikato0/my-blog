# 目标

将本次天气组件重构提炼为一篇设计复盘文章，发布到博客的“设计文档”分类。文章面向希望理解界面设计取舍的读者，重点说明视觉问题、信息层级和响应式布局决策，不展开大段实现代码。

# 内容结构

1. 说明重新设计的动机：原组件与预览稿不一致、信息堆叠导致高度过高、桌面端和移动端缺少不同的信息策略。
2. 说明统一视觉基准：以 `Responsive weather scene` 作为最终参考，桌面采用横向场景，手机采用竖向场景。
3. 复盘 PC 端布局：左侧突出地点/温度/天气状态，右侧承载图标和详细指标，六项污染物固定为一排，并通过压缩间距控制高度。
4. 复盘移动端布局：默认展示核心天气信息，完整数据折叠到下方，通过底部箭头展开。
5. 复盘背景氛围：PC 使用 `/pc` 背景接口，移动端使用 `/mp` 背景接口，配合渐变遮罩和颗粒纹理，失败时回退默认背景。
6. 解释信息优先级：核心天气、即时体感、环境数据、污染物浓度分层展示。
7. 解释动画调整：PC 从右侧缓慢进入，移动端减少不必要动画，并尊重减少动态效果偏好。
8. 总结设计经验：预览稿与实际组件共享视觉语义；响应式设计需要重排信息优先级；氛围效果服务于可读性。
