# 知识图谱集成设计

**日期：** 2026-09-07
**目标提交：** `349027dbee9414ec6574d9b75682e4957e309f74`
**目标分支：** `codex/knowledge-graph-integration`

## 目标

将上游的四层知识图谱完整替换当前标签图谱：分类 → 标签 → 文章 → 小标题。保留当前项目中与图谱无关的主题、内容与导航定制；不合并 upstream 的整条提交历史。

## 范围

### 纳入

- 知识图谱数据构建与 `GET /api/knowledge-graph.json` 数据端点。
- 图谱 Canvas 渲染、交互、物理模拟、筛选面板和节点详情面板。
- 分类页从 `TagGraph` 切换到 `KnowledgeGraph`。
- 图谱所需的样式、CSS 变量、导航和多语言词条。
- 删除旧的 `TagGraph.astro`、`tag-graph-controller.ts` 和 `tag-graph-data.ts`，以及全部运行时引用。

### 不纳入

- 目标提交之外的 upstream 中间提交或其他页面重构。
- 保留旧标签图谱作为并行入口或回退 UI。
- 对既有文章内容、分类体系或标签命名进行批量修改。

## 集成策略

采用精准移植，而不是直接合并 upstream 分支或盲目 cherry-pick：

1. 以目标提交的 29 个文件为功能清单。
2. 以当前分支版本为冲突文件的基线，逐个移植图谱所需的最小改动。
3. 先移植独立新增文件，再处理页面、数据工具、样式变量、导航和 i18n 等重叠文件。
4. 每个旧图谱文件删除前，确认不存在静态导入、动态导入、样式选择器或类型引用。
5. 保持改动局限于知识图谱能力，拒绝目标提交外的上游改动。

## 架构与数据流

构建期内容工具读取当前站点文章的分类、标签、URL、发布日期和 Markdown 标题，生成四层节点与关系边。`/api/knowledge-graph.json` 输出可缓存的图谱数据。分类页加载 `KnowledgeGraph.astro`，组件在客户端请求该 API，创建渲染场景、模拟器和 Canvas 渲染器；`GraphFilterPanel.astro` 通过数据属性驱动搜索、层级、分类、外观和动画筛选。

节点层级与预期行为：

- **category：** 分类节点，连接其所属标签。
- **tag：** 标签节点，连接分类与包含它的文章。
- **post：** 文章节点，跳转到文章 URL，并连接文章标题节点。
- **heading：** 小标题节点，默认关闭，需要时在图谱中展开。

## 冲突处理规则

- `categories.astro`：保留当前布局容器和页面约定，仅替换旧图谱入口及其数据准备逻辑。
- `content-utils.ts`：不覆盖当前项目的非图谱工具；仅增加知识图谱需要的内容读取或导出。
- 导航与 `link-presets.ts`：保留当前项目已有菜单配置，仅迁入图谱相关文字和链接排序调整。
- i18n：按当前语言文件结构补齐全部新增键，避免覆盖当前分支已有翻译。
- CSS：新增独立的知识图谱样式文件；仅从 `categories.css` 移除旧图谱选择器，保留当前分类浏览器样式与页面特有定制。

出现无法通过代码和测试判定的产品行为差异时，停止在该文件并向用户说明，而不是以覆盖方式消除冲突。

## 验收与回退

- Git 索引和工作区不存在未解决冲突标记。
