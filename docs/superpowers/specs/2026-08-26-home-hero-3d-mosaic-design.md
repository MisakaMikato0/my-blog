# 首页 3D 拼图滚动过渡设计

## 1. 目标

重做桌面端首页 Hero 的图片过渡，使其保留现有“碎片拼合 + 滚轮控制”的风格，同时解决以下问题：

- 拼图完成后突然放大；
- 拼图层仍在、另一张大图突然切入；
- 图片比例被拉伸或最终额外放大；
- 文字缩小造成视觉变形；
- 向上滚动时状态不能完整恢复。

手机端不使用这套动画，直接展示完整图片。

## 2. 已确认的交互效果

桌面端使用滚轮持续控制，时间线可正向和反向 scrub：

1. 顶部待机：马赛克碎片做 C 级强 3D 自动起伏，不跟随鼠标；
2. 开始滚动后的前 8%–10%：3D 起伏平滑压平，不瞬间停止；
3. 接下来：碎片回到网格位置，完成拼图；
4. 拼图完成后：完整图片短暂停留；
5. 继续下滑：同一张完整图片连续放大到刚好覆盖视口；
6. 图片放大阶段：标题和雨幕淡出，标题不缩小、不明显位移；
7. 图片到 cover 后：不再继续放大；
8. 首屏结束：Hero 整体平滑离场，下一段内容从底部进入；
9. 向上滚动：完整反向恢复；回到顶部后重新启动待机 3D 起伏。

## 3. 推荐方案

采用方案 A：在现有 GSAP、ScrollTrigger 和马赛克 DOM 结构上增强 3D。

不采用 Canvas/WebGL，因为本次目标是修复图片层切换和滚动状态，而不是重做渲染管线。保留现有 DOM 能降低响应式、资源随机选择、Astro 页面切换和可逆滚动的风险。

## 4. 组件职责

### `src/components/layout/HeroMosaic.astro`

- 生成马赛克碎片网格；
- 生成唯一的完整图片承接层；
- 保证随机选中的图片同时用于碎片和完成图；
- 移动端直接展示完整图片，不启动桌面动画。

### `src/utils/home-hero-motion.ts`

只提供纯计算：

- 碎片初始 3D 参数；
- 拼合完成位置；
- cover 缩放比例；
- 首屏固定距离；
- 窗口变化后的可重复计算。

该模块不直接操作 DOM。

### `src/utils/home-hero-controller.ts`

负责动画生命周期和状态协调：

- 创建和销毁待机 3D 动画；
- 创建 ScrollTrigger 时间线；
- 将待机状态平滑压平并交给滚动时间线；
- 控制碎片、完成图、标题、雨幕和 Hero 离场；
- 页面切换、前进后退和卸载时统一清理。

### `src/styles/components/home-hero.css`

负责静态视觉和响应式规则：

- `perspective`、`transform-style: preserve-3d`；
- 碎片阴影、景深、裁切和合成层提示；
- 手机端完整图片展示；
- reduced-motion 下禁用 3D 和滚动动画。

## 5. 时间线分段

| 进度 | 行为 |
| --- | --- |
| 0%–10% | 自动 3D 起伏压平，待机动画停止 |
| 10%–50% | 碎片从散乱位置回到网格，完成拼图 |
| 50%–65% | 完整拼图稳定停留 |
| 65%–90% | 同一个完整图片层放大到 cover |
| 90%–100% | 保持 cover，标题/雨幕淡出，Hero 离场，下一段进入 |

时间线中的每个阶段都只修改自己负责的属性，待机动画和滚动动画不能同时争夺同一组 transform 属性。

## 6. 图片层约束

- 所有图片视觉结果都来自同一个随机选中的资源；
- 完成图从拼合完成时的实际尺寸开始，不从 CSS 初始状态重新跳入；
- 最终缩放使用 `max(viewportWidth / imageWidth, viewportHeight / imageHeight)`；
- 不增加 `1.015` 等额外放大余量；
- 使用 `object-fit: cover` 保持比例，允许裁切但不允许拉伸；
- 独立 backdrop 不参与主滚动过渡，避免第二张大图淡入覆盖。

## 7. 异常处理

- 图片尺寸加载完成后触发一次刷新，重新计算 cover 终点；
- 窗口尺寸变化时调用 `ScrollTrigger.refresh()`；
- 快速滚轮和拖动滚动条直接按当前进度取值，不依赖逐帧累加；
- Astro 页面切换时销毁旧时间线、待机动画和雨幕实例；
- reduced-motion 下只展示稳定完整图片；
- 图片加载失败时保留背景色和文本，不展示空的半透明完成层。

## 8. 验收标准

1. 桌面端待机时有明显但可控的 C 级 3D 起伏；
2. 滚动前 8%–10% 内 3D 连续压平，无定格跳变；
3. 碎片拼合没有拉伸、错位或突然放大；
4. 拼图完成后有明显稳定停留；
5. 放大过程连续，最终只到刚好 cover；
6. 不出现第二张大图突然淡入；
7. 标题不缩小，只在图片放大阶段淡出；
8. 雨幕和标题淡出后，Hero 平滑离场，下一段从底部进入；
9. 向上滚动可以完整反向恢复；
10. 手机端直接展示完整图片，不启动桌面动画；
11. 全量测试、类型检查和格式检查通过。

## 9. 实施范围

预计修改：

- `src/components/layout/HeroMosaic.astro`
- `src/utils/home-hero-controller.ts`
- `src/utils/home-hero-motion.ts`
- `src/styles/components/home-hero.css`
- 对应的 motion 单元测试和必要的首页集成测试。

不修改移动端首页的内容结构，不引入新动画库，不重做图片加载和资源管理体系。
